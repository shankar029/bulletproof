3. Key interaction

4. UX before code

Projects → tasks → editor, plus Dashboard. URL preserves filters/page and Back navigation. Project list, task cards and inline editor stack below 720px without horizontal overflow.

Team planner       [Projects] [Dashboard]
Projects           Launch  [Add task]
[Create project]   [Search] [Status] [Priority]
Launch             Draft [todo]       [Edit]
                   Review [blocked]   [Edit]
                   [Previous] Page 1 of 2 [Next]
                   Editor: Title / Status / Dependencies / Priority
                   [Save task] [Cancel]

Titled dependency checkboxes; explain incomplete dependencies. Announce loading/empty/saved states; no results offers Clear filters. Pending save prevents duplication. Failure retains inputs and focuses an alert. Conflict offers explicit reload/discard; cancel restores saved fields. Success refreshes counts only after commit.

System font, neutral surfaces, blue focus/action, text-labeled error/success; native controls, visible focus, ≥44px targets. Verify keyboard, names, contrast and 390/1280px layouts. Automated checks do not certify WCAG conformance.

5. Data and decisions

Binding contracts and worked examples: v1 disk state becomes v2 status plus priority; API retains status. Expand dual-reader, migrate offline with backup, retire v1 writing, retain reading.

DecisionAlternative / rationale
Node + snapshot fileOver SQLite: bounded local use needs no database dependency. Lock + atomic replacement; no distributed/power-loss guarantee.
Global revisionOver per-task revisions: simpler graph consistency; explicit whole-state conflicts.
Plain DOM + node:testNo SPA/build burden. E19 supplies a real HTTP test pattern, not reusable app code.

Caller: const {revision}=planner.listProjects(); await planner.createProject({name:"Launch"}, revision); Use returned revision next. Stale writes fail; fetch current state before deciding. Lock/rollback remain internal.

6. Risks and proof

Reject corrupt schema/occupied lock. Pre-commit failures preserve bytes. Windows replacement needs a bounded experiment. Offline rollback loses later writes. Static allowlist, loopback Host/Origin checks and text rendering constrain local use; no hosted-service claim.

Proof: HTTP/restart (AC01–03), graph/query/count assertions (04–06), browser journeys (07–08), real migration (09), controlled original/minimized red→green (10), independent final reconciliation (11–12). Results live in the evidence ledger. Managed Python was subsequently found through uv; initial PATH-only absence and OS-temp prohibition are corrected research limitations.
