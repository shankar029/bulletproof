3. Execution and proof

  • Start: parent samples research citations, incorporates its OS-temp correction, reviews this design, accepts all ACs and records READY/REVISE/BLOCKED. Incoming implementer confirms P0 prerequisites. Browser availability and replacement behavior are explicit gates.
  • Test first: one behavior at a time. Begin with runnable public seams, then an assertion that fails for missing behavior, not a missing import. Preserve chronological red/green source hashes, input, command, expected/observed values and refactor regression evidence.
  • Test layers: native node:test through pure rules, real filesystem and HTTP; browser UI via designated agent-browser only. API tests do not replace UI proof. Every slice reruns delivered app tests and its browser journey; final pass covers the complete app and existing repo regression suite.
  • Environment: PowerShell, exact repository cwd recorded in tasks. Node 24.11.1 was observed. Python unavailable: record documented probe/idle-runner limitation; bounded native Node commands have wall/test deadlines but do not claim probe equivalence. Tool-managed OS-temp behavior is not the parent restriction mistakenly asserted in research.
  • Browser setup: missing-tool result already exists; parent may install agent-browser, inspect installed help, install/launch browser, then bind exact supported commands into the planned replay script. If launch fails, retain failed evidence and mark UI checks BLOCKED. No invented flags, silent Playwright substitution or false “all features passed”.
  • Coverage: every newly introduced branch requires a relevant scenario; collect native line/branch coverage and explain gaps. No new arbitrary percentage substitutes for assertions. Python metric/mutation gate remains unmeasured unless that prerequisite is actually resolved.

4. Evolution, diagnosis and recovery

I4 starts by reopening the real v1 checkpoint from disk and recording source/schema/revision. Parent adopts r2 from those observations: stop dependent tasks, refresh changed facts, invalidate v1-only evidence for v2 claims, retain earlier historical results, recheck affected design/readiness, then resume at I4.T1. A copied revision template without a real checkpoint/consumer reconciliation does not exercise the revision contract.

Migration is offline: dual-reader first, verified backup, atomic replacement, read/edit/restart proof, then remove v1 writer. Retain legacy reader and v1 fixture permanently. v1 binary cannot safely open v2. Rollback restores the verified backup only on isolated test data; it discards subsequent v2 writes and is not an automatic recovery action on user data.

I5 copies the known-good example into an owned workspace and injects exactly one filter-after-pagination change. Original seven-task HTTP scenario must fail on expected IDs and total; minimize it to two tasks, discriminate query-order versus parsing, then add/retain regression proof, repair the copy and rerun original + minimized + browser + release regressions independently. Never wire a fault switch into shipped code. No failure means no diagnosis PASS.
