Planner lifecycle — UX proposal

I1 · AC1–AC5 · Program design · Normative C5 contract

No human approval received. Proceeding only under explicit no-wait authorization; this is a proposed specification, not a rendered product or completed accessibility proof.

Users, routes and layout

The local planner user retires a project without deleting work, reads or exports it, and restores it when work resumes. Archive describes project lifecycle, never snapshot backup.

Team planner     [Projects] [Archived projects] [Dashboard]
Status / actionable error                     [Reload latest]
Projects or Archived projects     Selected project name [Archived]
[Create project]                  Totals
Project links                     [Archive project / Restore project]
                                  [Download CSV] All tasks, not just this page
                                  Search / status / priority / Apply / Clear
                                  Task cards / Add task / Pagination

Keep the existing sidebar/content grid. /?archived=true selects archive navigation; omitted or archived=false selects active navigation. projectId selects independent detail, even when absent from the sidebar. view=dashboard retains its existing meaning; archived filters navigation only, not global counts. Native link hrefs include navigation/filter state for new tabs and deep links.

Primary flows

  1. Archive: select active project → Archive project → confirm “Archive this project? Tasks will become read-only. You can restore it later.” → saving feedback → coherent refresh. Keep the project selected and its filters/page; move navigation to Archived projects. Announce “Project archived. Tasks are read-only.” Archive is available regardless of task statuses.
  2. Read: Archived projects → select project or open a direct project link. Display “Archived — tasks are read-only. Restore this project to make changes.” Preserve descriptions, status, blocked badges, priority, summaries, filters and pagination. Add/Edit remain visible but disabled with the explanation adjacent.
  3. Restore: Restore project → saving feedback → coherent refresh in active navigation, same project/filter/page → “Project restored. Editing is available.” No deletion confirmation is needed. An existing draft must be canceled or finished before either lifecycle action.
  4. Export: Download CSV → “Preparing CSV…” → one full-project snapshot download → “CSV download started.” Available in active, archived and legacy read-only detail. Button disables only during its request/loading. Do not claim the user saved the file. Failure keeps the page and focuses the error.

Only explicit Reload latest/navigation discards the draft; it is never retried or rebound to a newer revision.

Navigation and accessibility contract

Projects/Archived projects change the sidebar without discarding selected detail or task filters. Selecting another project resets page only. Filter and page-size changes retain existing reset rules. Dashboard clears task filters as today. Lifecycle success changes only the archive selector; browser Back/Forward reloads its URL without automatic writes. Explicit navigation/reload is the recovery/discard action; status text warns before using it after an error.

Reuse observed public/styles.css: 16px body, 28/22/18px headings, 16/24px spacing, 44px primary controls, existing semantic status/error surfaces and focus outline. No new visual tokens, icons, animation or CSS framework. Existing 719px breakpoint stacks sidebar above content; buttons wrap and long names/text wrap at 390px. Reduced motion remains respected by adding no motion.

Use real links, labeled buttons/forms and visible “Archived” text rather than color alone. Keep polite status, focused alert and keyboard ordering. After lifecycle refresh focus the replacement lifecycle button; after draft cancel focus Add task when enabled, otherwise the project heading with programmatic focus. Filters, pagination, download and Restore remain keyboard-accessible on archives. Test WCAG 2.2 AA contrast, target size, focus and labels rather than assuming reuse proves compliance.
