### Regression checks and approval limits

- **Fail-closed quality was not weakened by simplification.** Required unsupported metrics still produce incomplete/fail; no waiver, old-score fallback or threshold reduction was introduced. The stock probe's missing coverage/architecture collectors are a real remaining measurement limitation, not an approved complete-quality result. A missing collector cannot be replaced with a fixture receipt when claiming actual increment closure.
- **The guard remains a bounded local primitive.** Revised edge ownership, derived replay and separate source/contract binding remove the specific contradictory authorities and forward dependency. The six verbs still have concrete purposes; these revisions introduce no framework, factory, authentication claim or host API.
- **Conservative recovery is intentionally limited, not magically implemented.** The callback is implementable using the existing local `Popen` handle. Creation identity and whole-tree termination evidence may be unavailable on a platform; that run must remain blocked. A protocol fixture for environment-reset evidence does not establish that a live reset occurred or that the host offers one.
- **Scoped resume and temporal evidence survive the edits.** Current-pointer resolution, relevant binding invalidation, preservation of unaffected receipts, and consumption of earlier compatibility/red proof before the named action remain explicit. No new backfill or blanket-reset permission was introduced.
- **Independent validation remains future work.** The revised standalone, forward-edge, live-child crash and consumer cases are bounded tests of the changed contracts. Actual native-version behavior, quality measurements, per-increment verification/review and the fresh-agent experiments are still required. No implementation or feature test has run in this review.

No additional blocking regression was established within this bounded re-review. This is approval of the revised design dispositions, **not** implementation completion, an all-AC verification pass, human sign-off, authenticated isolation or a rendered page-count result. Parent owns rendering and subsequent planning; the historical review below is unchanged except for being labeled superseded.

### Coupling and proportionality assessment

**DR1 process-API clarification:** `(rc, stdout, stderr)` supplies no live child handle or PID; adding `env` does not change that. A minimal process-start/ownership seam must durably expose the owned child while the guard is alive, and explicitly handle a crash between spawn and durable recording. A callback alone does not eliminate that interval. Without reliable ownership/termination proof, recovery must report unsupported/blocked for that run, not clear admission based on the dead guard PID. This requires no general orphan-management framework.

The follow-up inspection used the same artifact hashes. DR5 is the additional actionable coupling finding; it takes priority over cosmetic reduction of document length. The design's module grouping does not itself force a future dependency, but the independently usable measurement boundary must be explicit rather than left for the implementer to redesign.

`--measurements` has a defensible **final-scope** purpose: the existing probe does not collect diff coverage or architecture-rule evidence, and AC02 requires honest handling of that proof. Nevertheless, imported receipts, applicability/exemption review and bootstrap acceptance are **not prerequisites for fixing the initial completeness/freshness bugs**. Explicit required policy plus fresh collection can correctly report unavailable required observations as incomplete/fail without adopting any workflow. Do not require review/receipt machinery merely to emit that honest failure. If imports/exemptions remain, their authority validation belongs at a defined boundary; a plain number or caller-authored exemption is not enough. This is not a request to waive coverage, make missing architecture inspection not-applicable, or label I1 overall quality passed while proof is absent.

The six verbs are not independently evidence of overengineering: status, admission, returned-proof import and closure serve actual workflow scenarios; adoption serves AC07 and recovery serves real crashes. No generic transition language, plugin framework or host API is needed. The excess with a concrete correctness cost is the duplicate writable authority in DR3 and the unresolved coupling in DR5, not the verb count alone. Review/bootstrap records can be justified where they bind accepted policy/current design, but must not become mandatory ceremonial setup for an ordinary standalone measurement invocation.

DR6 adds a separate scope correction: do not turn an execution-location preference into a product requirement and widen the patch to existing runners without an AC-grounded need.

DR7 distinguishes withheld experimental inputs from adversarial access prevention. The former is relevant to the requested diagnosis; the latter is not an unstated prerequisite for the entire feature. A single observed exercise remains bounded evidence, never authenticated isolation or general model-effectiveness proof.

## Implementability and evidence limits

Python stdlib hashing, JSON, exclusive creation and same-directory atomic replacement, plus native Node custom reporters, can implement the core without dependencies. Node 22's published `test:pass`, `test:fail` and `test:plan` contracts expose test identity, nesting, suite metadata and wrapped error causes; these support the proposed distinction between actual failures and quoted logs. This API inspection is not proof that the proposed classifier already handles every event shape. Supported-version fixtures must establish that, with unknown shapes remaining ungraded.

Measurement honesty, guarded transition/resume, and document/experiment integration can be separable increments with independent tests **once DR5's dependency boundary is explicit**. Independent reviews and closure must apply before dependent work, not only at final ship. Available stdlib patterns do **not**, as currently specified, establish DR1's child-lifetime guarantee.

No source/tests were changed or executed, no dependencies installed, no agents spawned, and nothing published. No unavailable analyzer, held-out experiment, fresh-agent run or historical baseline was counted as a new passing measurement. Parent dispositions and rendering are intentionally outside this review.
